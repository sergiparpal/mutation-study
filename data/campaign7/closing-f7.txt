# Seventh campaign, step 2: the f7 runs whose closing message names a test as
# showing a bug (PROTOCOL.md, "Procedure"), one per line:
#   f7 <bug> fault|other <the words that say what the bug is>
# `fault`: one of the bugs named is a behaviour that the bug's source patch
# changes, and what the message says the behaviour should be is what the fixed
# version makes it ("Outcomes"). `other`: none is. All 40 closing messages
# were read on 28 November 2026 (./bin/audit-campaign7.py data/campaign7
# --closing), and each line was judged against the bug's source patch in
# Defects4J (framework/projects/<project>/patches/<id>.src.patch), before
# anything was measured.
#
# Where a message allows more than one behaviour, it names the fault when the
# fixed version's is one of them: Cli-32 ("a valid wrap position (or -1)"; the
# fixed version returns 4) and Csv-4 ("null or an empty map"; the fixed
# version returns null).
#
# Two messages name the fault of another bug of the sample, in code that is
# the same in both versions of the bug they were run on: Cli-10's names
# Cli-28's (processProperties' break), and Gson-4's names Gson-15's
# (value(double) and the lenient flag). Both are `other`.
#
# The 26 runs listed are the 26 that left a test out at acceptance. Not
# listed: the 14 runs whose message names no test as showing a bug, none of
# which left a test out: Cli-12, Cli-38, Csv-7, Csv-8, Csv-10, Csv-16, Gson-3,
# Gson-5, Gson-6, Gson-8, Gson-14, Lang-13, Lang-52 and Lang-65. Gson-8's
# message reports, with no test, that newInstance(null) crashes the JVM
# instead of throwing NullPointerException. In the fixed version
# assertInstantiable throws NullPointerException there.
