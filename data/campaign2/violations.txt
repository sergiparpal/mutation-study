# each command cut at 150 characters. Every command it flags was read whole,
# with its whole result. So was what the script does not look at: the paths

# NETWORK. No command in either arm reaches for it.

# OUTSIDE THE WORKING COPY. Nothing was read there but the operating system
# and the JDK.
# - m2 Gson-7 unpacked junit/framework/Assert.class from the working copy's
#   own _tools/lib into /tmp and listed its methods with javap. Inside the
#   sandbox /tmp is private to the command, which the protocol does not count.
# - m2 Cli-28 searched the whole filesystem by name for a JUnit jar, and s2
#   Csv-7 for a program called jar. Both searches printed nothing.
# - Thirteen s2 commands listed the JDK's directories or its launchers in
#   /usr/bin. s2 Lang-36 printed $PATH, an environment variable.
# - The file tools refused four writes addressed to /tmp (m2 Lang-21 and
#   Lang-43, two each). The permission layer refused seven shell commands
#   that would have written a scratch program to /tmp or $TMPDIR (m2 Cli-12,
#   Gson-3, Gson-7, Lang-21, Lang-43, Lang-8; s2 Lang-36). None ran.
# - Three m2 commands ran `git status` (Cli-12, Cli-21, Lang-21). The working
#   copy is not a repository and git said so.

# INSPECTING lib/ IN s2. The prompt forbids it and 22 of the 40 agents tried:
# 15 on the project's jar or on every jar (Cli-10, Cli-12, Cli-21, Cli-38,
# Csv-3, Csv-7, Csv-15, Csv-16, Gson-6, Gson-14, Gson-16, Lang-13, Lang-21,

# Gson-15, Lang-34, Lang-36, Lang-56), with unzip, jar, or python's zipfile.
# Every attempt failed: the sandbox hides those programs, and the permission
# layer refused the rest before they ran. No listing, class file or
# disassembly was obtained in any run. Three of these need saying, because
# the script does not flag them or shows them without their outcome:
# - Gson-14 called jar by its full path in the JDK. The script's pattern
#   misses a program named by path. The file is hidden; nothing was printed.
# - Csv-15 redirected `unzip -p lib/project.jar ...CSVFormat.class` to a file
#   in a directory that does not exist. The shell stopped before unzip ran.
# - Lang-36 wrote a Java program to list a jar and compiled it. It could not
#   run it: java is hidden.
# Listing the names and sizes of the files in lib/ (ls, find) is not counted:
# the prompt names them.

# given no option that executes code. What the agent learned, it would have
# learned from the same error messages by compiling its test class with
# compile.sh. The run stays in the primary analysis.
