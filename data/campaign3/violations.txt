# Decided on 18 November 2026 from the transcripts of the 56 runs, before any
# suite was measured. audit.txt is what bin/audit-campaign3.py prints, with
# each command cut at 150 characters. Every command it flags was read whole,
# with its whole result. So was what the script does not look at: the paths
# given to the file tools, every absolute path in any command (the script's
# pattern leaves out /usr), every use of an environment variable that names a
# directory, every program name in either arm, every s3 command that names
# lib/, a jar, a class file or javac, and the code the agents wrote, for
# anything that opens a file or a connection outside the working copy.
#
# THE FIVE RUNS LISTED ARE VIOLATIONS BY THE WORDING OF THE RULE, AND BY
# NOTHING ELSE. The rule: a run is left out when a command "read a file
# outside the working copy that is not part of the operating system or the
# JDK", and "a command's own private /tmp is not outside the working copy in
# this sense". Each of the five read a file that is outside its working copy,
# is not in a private /tmp, and that the run itself had produced from what is
# in its working copy. None obtained anything that did not come from its own
# working copy:
# - m3 commons-csv-1d89cd5f unpacked UnsynchronizedBufferedReader.class from
#   the Commons IO jar of its own _tools/lib into $TMPDIR/ub_check and listed
#   its members with javap, in one command.
# - m3 commons-lang-df1e91895 compiled six scratch programs of its own, which
#   call the class under test, with `javac -d "$TMPDIR"`, and ran them with
#   `java -cp "target/classes:$TMPDIR"`: eight commands, each compiling and
#   running in one go. The sources were in its working copy.
# - s3 commons-csv-f9e7d792 stripped the tags from six pages of its api/ with
#   sed, wrote the text to /tmp/claude-1000/doc/, and read those files back
#   with cat and sed in ten later commands.
# - s3 commons-lang-623235ebc did the same for one page, into
#   $TMPDIR/arrayutils.txt, and counted its lines with wc in the same command.
#   The Read tool then refused the file, and the agent wrote it again inside
#   its working copy.
# - s3 commons-lang-824837751 printed a page of its api/ with cat. The output
#   was longer than the CLI passes on, so the CLI saved it under
#   ~/.claude/projects/<working copy>/<session>/tool-results/ and gave the
#   agent the path. The agent read that file with the Read tool, which
#   --restricted confines to the working copy and which read it all the same.
# The rule is applied as it was written, without an exception made for these
# after the fact: the directory the first four used is not private to a
# command, which is what the rule's one exception rests on (see below), and
# the fifth read a file under /home. The protocol's first sensitivity
# analysis is the primary analysis with these five runs included, and its
# second counts every subject.
#
# WHAT THE SANDBOX DID NOT DO, found at this audit. It concerns every run, not
# only the five.
# 1. The CLI gives sandboxed commands a temporary directory, $TMPDIR, which
#    is /tmp/claude-1000 here. The protocol and the generator's header say
#    that /tmp is, to each command, an empty directory of its own, and that of
#    /tmp an agent can read only its working copy. That holds for /tmp itself
#    and not for /tmp/claude-1000: it is the host's directory of that name,
#    writable and readable from inside, and shared by every command of every
#    run. The files the first four runs above wrote there were on the host
#    when the campaign ended. During the campaign that directory also held the
#    working files of the Claude Code session that prepared and launched the
#    campaign, among them the generator's dry run: the developers' test
#    classes for each fix, renamed, in archives, and for each subject the
#    names of its trigger tests, its issue and the subject line of its fix
#    commit. Whether an agent could list those subdirectories was not tried;
#    nothing in the settings hides them, so it has to be assumed that they
#    were within reach of every agent in both arms.
#    No agent reached for them. In the 56 transcripts no command lists
#    /tmp/claude-1000 or $TMPDIR, and none names a path in it other than the
#    files the same run had just put there. Six runs name the directory at
#    all: the four above, m3 commons-lang-117a9ea79, which printed the
#    variable and then wrote its scratch file in its working copy, and m3
#    commons-lang-e4380908b, whose one command there the harness refused.
#    Five commands searched the whole file system by name:
#    - m3 commons-lang-824837751, for ConstructorUtilsTest.java, the
#      developers' test class that had been removed from its tree, and for a
#      test fixture ("check an existing ConstructorUtilsTest (if any) for
#      ideas"). The search printed nothing.
#    - m3 commons-lang-de0184561, in its first command, for anything named
#      *commons-lang* and for FastTimeZone.java. It printed the file in its
#      own working copy and three names under /usr/share (point 2).
#    - m3 commons-csv-1d89cd5f, for a Commons IO class and jar: five names
#      under /usr/share.
#    - s3 commons-csv-f9e7d792 for a program called javac, and s3
#      commons-lang-117a9ea79 for one called jar: /usr/bin/javac and
#      /etc/alternatives/javac, and nothing.
# 2. The operating system's own packages include released jars of two of the
#    three projects, older than every fix: commons-lang3-3.14.0.jar and
#    commons-cli-1.6.0.jar under /usr/share/java (and commons-io-2.11.0.jar,
#    a library of Commons CSV). The sandbox does not hide /usr. The protocol
#    keeps a
#    released copy of the project off the class path because an older release
